# 服务端功能说明

服务端没有给住客点的页面。它是一直开着的程序：用户端和管理端把「登录、查房、下单、支付、核销、商家入驻、会员优惠券」这些请求发给它，它检查是否允许、把结果存进数据库，必要时再去问微信、支付宝、短信、地图、对象存储这些外面的服务。

可以把它理解成总台。两个前台（用户端、管理端）说的话，都由总台记账，并在需要时给外面的公司打电话。

数据库脚本在 `jdms-server/db/jdms.sql`。开发库名建议是 `jdms`。门店、房间、订单、用户、会员、优惠券、发票、系统配置都记在这里。

启动类是 `com.sqx.SqxApplication`。端口是 **9129**，所有接口都在 `/sqx_fast` 下面。接口列表在：

http://127.0.0.1:9129/sqx_fast/doc.html

Redis 用于登录态、系统配置缓存等，启动前需要先开 Redis。

下面先说它为两个前台做哪些事，再说业务规则，最后说它会主动连接哪些外面的服务。

## 它为住客 / 商家 / 员工（用户端）做的事

这些都是用户在手机里点一下之后，由服务端完成的：

- **注册和登录**：检查手机号和短信验证码，或检查密码 / 微信授权。通过后发给用户登录凭证（JWT）。之后需要登录的请求都要带这张凭证，否则视为没登录。
- **首页数据**：返回轮播、热门推荐门店；支持按国内酒店 / 钟点房 / 民宿筛选。
- **定位与检索**：按城市、经纬度、关键词（酒店名 / 地名 / 地标）查询可订门店。
- **门店与房型**：门店详情、标签、评分、地址；房型列表、库存、原价与会员价、设施分类。
- **下单与支付**：创建住宿订单，处理优惠券抵扣、发票信息；对接微信 / 支付宝 / 余额等支付，支付回调后改订单状态。
- **订单流转**：待支付、待核销、进行中、已完成、已取消、退款 / 售后等状态变更。
- **核销与退房**：校验核销码；记录入住 / 退房相关操作。
- **评价**：住客对门店打分、写评价；管理端与门店详情可查看。
- **收藏、足迹**：收藏门店、浏览足迹同步到云端。
- **会员与钱包**：会员套餐、开通 / 续费；钱包余额、充值、提现申请、资金明细。
- **优惠券**：领券、我的券、下单选用。
- **发票**：下单申请开票、发票记录查询。
- **商家入驻**：提交门店资料、审核状态查询；审核通过后的商家中心（房间、订单、员工、商户钱包）。
- **员工能力**：店员协助订单核销等（账号由商家添加）。
- **推广邀请**：邀请关系、收益相关数据。
- **消息 / 客服 / 帮助 / 反馈**：站内消息、帮助文章、意见反馈；客服方式由后台配置。
- **文件上传**：头像、门店图、房间图等，可存本机目录或对象存储。

## 它为管理端做的事

- 工作人员登录（账号 + 密码 + 图片验证码）。
- 数据中心：用户、订单、门店等概况数字。
- 用户中心、注销信息。
- 酒店列表与房间管理、商家入驻审核。
- 订单中心、财务中心。
- 会员配置、会员特权、优惠券管理、时间配置。
- 首页装修（轮播等）、分类管理、帮助中心。
- 消息中心、评论中心、发票管理、聊天记录。
- 推广中心相关配置。
- 系统配置：基础域名、登录认证、支付、短信、文件存储、客服、协议等。
- 系统管理：管理员、角色、菜单、操作日志。

## 订房与核销业务规则（通俗说明）

1. **选房下单**：用户端选定门店、房型、入住离店日期后创建订单；未支付可取消。
2. **支付成功**：微信 / 支付宝 / 余额支付成功并收到回调后，订单进入待核销（或按配置进入下一状态）。
3. **到店核销**：住客出示订单二维码 / 条码，或商家 / 员工输入核销码；服务端校验后标记已核销 / 入住中。
4. **退房完成**：商家侧完成退房后，订单可进入已完成，住客可评价。
5. **取消与售后**：已支付订单取消可能产生费用提示；退款 / 售后以后台规则与人工处理为准。
6. **会员价**：房型可配置会员价；用户是会员时下单可见更低价格（以后台配置为准）。

## 商家入驻业务规则（通俗说明）

1. 用户在「我的 → 商家入驻」提交门店类型（酒店 / 民宿）、名称、电话、地图位置、封面与轮播、标签等。
2. 管理端「商家入驻」审核通过或驳回（驳回可写原因）。
3. 通过后，该账号可进商家中心管理房间、订单、员工与商户钱包。
4. 店主可添加员工；员工登录后协助核销。

## 对接了哪些外面的服务

下面每一项都是服务端真的会向外发送请求的。密钥没填时，它不会假装成功，用户端会看到失败提示。

### 短信

注册、验证码登录、找回密码等由服务端发短信。工程支持模拟发送、短信宝、阿里云、腾讯云等，具体走哪一家以管理端「短信通道」配置为准。

- 腾讯云短信：https://cloud.tencent.com/product/sms
- 阿里云短信：https://www.aliyun.com/product/sms

### 微信登录

用户选择微信登录时，服务端用小程序 / 公众号 / App 的 AppId 与 Secret 换取用户标识。密钥在管理端「登录认证」中配置。没配好时，用户端会提示微信登录暂未开通。

微信公众平台：https://mp.weixin.qq.com/

### 微信支付 / 支付宝

用户订房、开通会员、钱包充值时，服务端向微信或支付宝下单，并把拉起支付需要的信息交回手机。支付完成后，对方访问服务端的通知地址，服务端核对之后，再把订单改成已支付、发放权益。

- 微信支付商户平台：https://pay.weixin.qq.com/
- 支付宝开放平台：https://open.alipay.com/

### 图片存储

上传接口按配置走 **本机磁盘目录** 或 **阿里云 OSS** 等。OSS 未配好时，可先用本地上传路径联调。阿里云 OSS：https://www.aliyun.com/product/oss

### 地图

定位当前位置、地图选点、导航依赖地图相关能力与浏览器 / 手机权限。密钥与开放平台配置按你使用的地图服务填写。

## 这些不是外面的公司

- **门店、房间、订单状态、评价、收藏足迹**：只改自己数据库里的数据。
- **优惠券发放与核销记账、会员权益标记**：自己的服务器处理。
- **推广佣金记账、提现申请**：系统只记录申请与审核结果；真正打款仍需人工按用户填写的收款信息处理。
- **在线客服消息 / 帮助文章 / 反馈**：自己的服务器保存。
- **操作日志、权限、角色**：只约束管理端工作人员。

## 两个前台怎样和它配合

用户端和管理端都不直接「自己改数据库里的门店和订单」。它们把请求发给服务端，服务端再决定要不要去问微信、短信、图床或地图。

所以：

- 服务端没启动时，两个网站都能打开界面，但登录、列表、下单、支付都会失败。
- 外面的密钥只配在服务端能读到的配置（管理端「系统配置」写入库表，或环境相关 yml）里。只在用户端页面上改文字，不会变成已经开通了微信支付。
- 管理端改完门店、房间、会员 / 优惠券配置并保存后，用户端下次请求才会用到新内容。
